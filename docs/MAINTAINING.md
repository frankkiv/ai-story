# 維護指南：時間線與模型評比

這兩塊會隨新聞一直變。本文件說明資料放在哪裡、格式是什麼、更新時要注意什麼。

## 共通原則

- **中英兩版一起改。** 時間線事件、`SERIES`、`EVENTS`、`ROSTER`、`MX` 這些資料在中文頁（根目錄）和英文頁（`en/`）各有一份，結構完全一樣，只有文字欄位（說明、備註、分級名稱）要翻成英文。先改中文版，再把同一筆資料改進英文版，最後確認兩邊筆數一致。

1. **先查證再寫。** 日期和數字以官方發表文章為準；第三方彙整網站（llm-stats、benchlm、morphllm、felloai 等）只能當線索或補充，並在來源列出。
2. **標清楚來源類型。** 廠商自報與第三方重測不能混在同一欄而不說明。
3. **不確定就說不確定。** 月份查不到用「2026 上半年」或在備註寫「月份未確認」；分數說法不一就不放，在備註說明。
4. **改完更新「資料來源」區塊和頁尾日期。**

## A. 時間線（`history.html`）

### 資料位置

`<ol class="tl" id="tl">` 裡的 `<li>`，依時間由舊到新排列。三種項目：

**階段標記**（顧問、師傅、管家、包工頭）：

```html
<li class="tl-era"><span class="en">師傅</span><b>開始自己動手</b><span class="es">2024 年底起，AI 拿到工具，直接在你電腦裡做事。</span></li>
```

**大事件**（卡片，可加白話說）：

```html
<li class="ev big" data-cat="agent" data-year="2025" style="--c:var(--l-new)"><span class="dot"></span><div class="evc"><span class="evm"><span class="d">2025.02</span><span class="cat">Agent</span></span><h3>標題</h3><p>內文，兩三句。</p><p class="tl-elder"><b>白話說</b>一句比喻。</p></div></li>
```

**小事件**（一行）：

```html
<li class="ev small" data-cat="model" data-year="2026" style="--c:var(--l-hist)"><span class="dot"></span><div class="evc"><span class="evm"><span class="d">2026.07</span><span class="cat">模型</span></span><b>標題</b><span class="sm">一句說明。</span></div></li>
```

### 欄位

| 欄位 | 值 |
|---|---|
| `data-cat` | `model`、`agent`、`china`、`infra`（對應上方篩選按鈕） |
| `style="--c:…"` | model → `var(--l-hist)`、agent → `var(--l-new)`、china → `var(--l-mem)`、infra → `var(--l-skills)` |
| `data-year` | 四位數年份，右下角年份標籤用它 |
| `.d` | 顯示日期，格式 `YYYY.MM`；不確定用 `2026 秋`、`2026 —` |
| `.cat` | 顯示分類文字：模型、Agent、中國、基礎設施 |

### 規則

- 大事件用在「改變了人怎麼用 AI」的轉折，小事件用在「同類事件中的一個」。目前約 31 個事件，大事件約三分之一。
- 平衡廠商：Anthropic、OpenAI、Google、中國各家的重要發表都要收。agent 工具的例子可以以 Claude Code 為主，hero 下方的說明已經交代這點。
- 時間線上不放分數圖表；提到分數時用一句話，詳細的放 `bench.html`。
- 新增分類要同時改：篩選按鈕（`.tl-filter`）、分類色、本文件。

## B. 模型評比（`bench.html`）

所有資料都在頁面最下方的 `<script>` 裡，是普通的 JS 陣列，直接改即可。

### 1. `SERIES`：能力曲線（SWE-bench Verified）

```js
{"key": "a", "name": "Anthropic", "color": "var(--l-skills)", "dy": 0,
 "pts": [["Claude Opus 4.8", "2026-05", 88.6], ["DeepSeek V4 Pro", "2026-08", 80.6, 1]]}
```

- 每點 `[名稱, "YYYY-MM", 分數, 月份推估?]`。第 4 個元素為 `1` 時畫空心圓。
- 只放「發表月份確定、而且有廠商公布的 Verified 分數」的旗艦。
- `dy` 調整線尾標籤的上下位置，避免重疊。
- 橫軸範圍在 `t0`、`t1`（`mon("2024-07")`、`mon("2026-12")`），跨年時要延長。
- 注意：OpenAI 從 2026/2 起不再公布 Verified，Verified 也已接近滿分，所以這張圖主要是歷史紀錄。新模型優先放進名冊和對照表。

### 2. `EVENTS`：曲線上的直線標記

`["YYYY-MM", "標籤"]`，最多四五個，避免擠在一起。

### 3. `ROSTER`：模型名冊

```js
["a", "Claude Opus 5.5", "2026.09", "2026-09", "旗艦", null, 89.9, "備註"]
```

| 位置 | 意義 |
|---|---|
| 0 | 廠商：`a` Anthropic、`o` OpenAI、`g` Google、`c` 中國 |
| 1 | 模型名稱（要和 `SERIES` 裡的名稱完全一樣，點曲線才會標出這一列） |
| 2 | 顯示日期：`YYYY.MM`、`2026 上半年`、`2026`、`—` |
| 3 | 排序用的 `YYYY-MM`；日期不確定時填一個合理的月份 |
| 4 | 等級：旗艦、中型、小型、推理、最高一級、限合作夥伴…… |
| 5 | SWE-bench Verified（廠商自報），沒有就 `null` |
| 6 | SWE-bench Pro（多半是廠商自報），沒有就 `null` |
| 7 | 備註，例如「月份未確認」「開放權重」 |

### 4. `MX`：同一張表上比（`#matrix`）

```js
["a", "Claude Opus 5.5", "旗艦", 59.1, 59.6, 1509, 4, 20, 0, ""]
```

| 位置 | 意義 |
|---|---|
| 0 | 廠商代碼（同上） |
| 1 | 名稱 |
| 2 | 等級 |
| 3 | Artificial Analysis 綜合指數（版本寫在表頭，目前 v5） |
| 4 | Terminal-Bench 4.0（第三方重測） |
| 5 | LMArena 文字排行 Elo |
| 6, 7 | API 價格：每百萬 token 輸入、輸出（美元），未公開填 `null` |
| 8 | 開放權重填 `1` |
| 9 | 備註（例如優惠價期限） |

- 這張表的原則是**只放第三方數字**。考試版本換代（例如 AA 指數 v5 → v6、Terminal-Bench 4.0 → 5.0）時，整欄一起換，並改表頭的 `<small>` 和下方說明 `.mx-key`。
- 每欄最高分會自動標綠色。
- 更新時同步檢查表格下方的快照日期說明。

### 5. 廠商自家表（`table.mx.vt`）

直接寫在 HTML 裡，目前是 Anthropic Opus 5.5 發表文的表。換成更新的發表時，保留「同一個考試，自報 vs 第三方差多少」這個對照的用意。

### 6. 文字區塊

- `#why`：分數為什麼不能全信，五個原因加「怎麼看」。原則性內容，通常不用改；有新的具體例子可以替換。
- `#strengths`：誰擅長什麼。每次主力模型換代都要重寫，依據放在說明文字裡（第三方數字、廠商表、評測網站評語）。
- `.names`：各家命名對照。新的等級名稱（例如 OpenAI 的 Sol／Terra／Luna）出現時更新。
- `SRC` 字串和 `#refs`：資料來源，每次更新都要改查詢日期。

### 建議的更新節奏

- **有大模型發表時**：加進 `ROSTER`；如果是主力模型，更新 `MX` 和 `#strengths`；時間線加一個小事件。
- **每月一次**：重抓 `MX` 的第三方數字，更新快照日期。
- **每季一次**：重新檢查 `#why` 的例子是否過時，命名對照是否完整。

## C. 捲動敘事導覽（`journey.html`）

### 資料位置

- **旁白段落**：`<div class="steps">` 裡的 `<section class="step" data-step="N">`，章節標題是 `<div class="chap">`。這些段落畫面上看不到（只留給螢幕閱讀器，也當作捲動的觸發點）；捲到哪一步，`go()` 就把那一步卡片裡的 `<p>`（含白話說）複製到舞台底部的說明欄 `#narr`。所以改文字只要改這裡，不用改兩個地方。
- **舞台設定**：頁尾 `<script>` 的 `S` 陣列，一步一筆，順序和 `data-step` 一一對應。欄位：`ch` 章、`name` 步名、`sub` 大字幕（關鍵字用 `<em>`）、`term` 名詞卡、`hot` 要亮的元素、`cam` 鏡頭框住的元素（省略就用 `hot`）、`fit` 看全貌、`pk` 小方塊停在哪、`tour` 小方塊依序經過的點、`kind` 小方塊樣式、`beam` 哪條管線跑光線（加 ` up` 往上）、`lit` 哪個封面亮起、`st` 舞台狀態 class。
- **地圖**：`#scene` 裡的 `#z-pc`、`#pipe`（路線）、`#z-srv`、`#pipe2`、`#phone`。

### 新增或刪除一步

1. 加旁白段落，把後面所有 `data-step` 和「第 N 步」往後順延。
2. 在 `S` 陣列同一個位置加一筆。
3. 改 `go()` 裡的總步數（`n < 16`、`Math.min(n, 15) / 15`）和三個封面展開的門檻（`z-pc` 第 1 步、`z-srv` 第 6 步、`phone` 第 14 步）。
4. hero 和 meta description 裡的「十五步」一起改。
5. 中英兩版（`en/journey.html`）同步。英文頁的 `S` 陣列結構、`id`、class 與中文版一致，只換文字。

### 規則

- 內容要跟 `tech.html` 對應段落一致；改了那邊的說法（例如 cache 時效、同步方式），這頁也要跟著改。
- 距離、延遲、token 編號都是示意或估算，頁尾要寫清楚。
- 改完至少在 390×844 和 1280×900 從頭捲到尾看一次，確認每一步鏡頭都框得到亮起來的地方，且沒有橫向捲動。
